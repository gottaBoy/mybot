# 计划修订与模型检查

更新日期：2026-11-03。

状态：V2 静态设计交互，待用户评审。没有执行器、真实模型请求、任务提交或权限系统接入。

## 1. 本轮要解决的问题

先前“要求修改”直接进入通用新任务页，会丢失失败原因与运行版本。模型选择也只展示下拉项，容易让“配置存在”被理解成“能力可用”。

本轮分别补成两个有前后文的操作：

```text
任务或成果 -> 要求修改 -> 计划 v3 草稿 -> 检查修订影响
                                          -> 提交修订（禁用）

Control Panel -> 选择模型 -> 检查连接与能力 -> 配置差异预览
                                                 -> 应用（禁用）
```

这两条路径不改变已经结束的 Run 02，也不会把历史验证和授权继承为新运行已通过。

## 2. 修订草稿

入口：任务标题处“要求修改”、成果页“要求修改”、Super-agent 的“修订执行计划”。

编辑内容：

- 修订目标。
- 验收要求。
- 两个固定阶段的名称与交付要求：开发修复、重新验证。
- 修订原因。

第三步固定为人工审查，不能在设计稿里删除来绕过门禁。角色模型引用 Control Panel 的本地草稿，返回后同步显示，不改写历史模型配置。

右侧保留失败依据：

- Run 02 / test-report。
- 期望扣款 1 次，实际扣款 2 次的示例结果。
- 候选代码 d4e5f6、项目基线、限定目录。
- 返回完整测试证据的入口。

大屏的目标与验收并排，手机逐项编辑。表单均可用键盘，错误与输入关联，就近提示；空值或不符合长度约束时不能预览。

## 3. 影响预览

预览区分：

| 对象 | 行为 |
| --- | --- |
| 计划 v2 / Run 02 | 保留原始事实、历史成果和失败结果 |
| 计划 v3 草稿 | 只展示建议目标、下一次步骤与交付要求 |
| 验证 | 新成果必须重新执行；旧测试不证明修复成功 |
| 写入授权 | 不能复用旧授权，执行前重新检查 |
| 模型与资源 | 仍是未应用草稿，需要检查连接和能力 |
| 人工审查 | 应用变更、提交、合并、发布均未自动获准 |

预览后可继续编辑；输入保留在当前文档内存中，刷新恢复默认建议。提交保持禁用。不会生成新 Run、改变 Run 02 或伪造审计事件。

用户输入显示为文本，渲染前转义，不能作为 HTML、工具指令或真实执行请求解释。

## 4. 模型检查面板

每个角色的模型选择下方增加“检查连接与能力”。原生模态对话框展示：

- 当前角色、拟选择的样例模型。
- 连接配置和拟发送位置。
- 模型用途声明。
- 身份、工具/结构化输出、上下文容量、数据区域等检查项。

所有能力标明未验证；“本地”“远程”只是样例连接草稿，不是已建立的连接。用途声明不等于实测结果。

开发模型从 A 切到 B 的样例会提示拟发送至外部服务，要求确认资料外发范围。只改变草稿，不能自动扩大工具或目录权限，不能自动测试或应用。

模态框打开时锁定背景滚动，键盘焦点留在模态内。关闭或 Escape 后返回原按钮，避免用户在长表单中丢失编辑位置。

## 5. 本轮验证

矩阵：23 个页面/状态、6 个视口，共 138 项渲染；19 条交互。

新增检查：

- 从失败任务进入修订，编辑后预览，再返回编辑和原任务。
- 非法和空输入被阻止，恢复建议、刷新重置。
- 计划草稿导航到 Control Panel 后返回仍保留编辑。
- 类 HTML 输入只显示为文字，不执行。
- 模型检查的未连接/未验证状态、模态焦点与背景滚动。
- 远程模型草稿的外发提示与配置预览。
- 历史状态、测试结果与应用/提交禁用保持不变。

最新结果：[verification.json](../design/review-v2/evidence/verification.json)。静态检查不是业务执行、安全隔离、连接真实性或用户体验验收。
