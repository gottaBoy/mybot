# UI 迭代记录

更新日期：2026-11-07（本轮环境日期；以下历史日期原样保留）。

原则：每轮先聚焦真实研发操作，保留前后截图、技术检查和用户反馈；自动检查通过不等于用户体验或视觉通过。

## 1. V1 反馈

用户明确评价“太丑了，不高级”。

记录的设计问题：

- 通用后台列表和大量细分隔线，缺少研发工作空间的组织。
- 小字与低对比内容过多，任务、调用、成果之间层级不足。
- 静态布局虽然能展示信息，但主要操作路径不够直接。

V1 仅保留作对照，不作为当前视觉基线。

## 2. V2 第一轮：两个关键画面

用户进一步提供 Cyrene-Agent、DeepSeek Super-agent 等公开参考，并要求“不断迭代，UI 体验要加强”。

本轮提案：石墨色双栏研发空间。不是复制参考页面或陪伴人格；主题与布局仍待用户确认。

### 任务工作区

- 默认打开任务，不以泛化仪表盘或营销首页作为第一屏。
- 左侧工作记录、Agent 分工和计划，右侧直接检查候选代码或测试。
- 原始目标、计划按需展开，避免已知背景挤占当前结果。
- 固定输入区与主工作区分开；输入禁用，不误导为真实可执行应用。
- 执行结束、验证失败、人工待审查继续分开表达。
- 未通过验证时应用变更禁用，保留真实动作边界。

### 调用分析

- 保留时间线、调用归属、失败尝试和用量未知状态。
- 全部、失败、模型、工具可实际筛选静态记录。
- 失败行进入详情并关联重试，不能把所有调用都指向同一个错误。
- 片段计量与运行总量区分，不补造成本或 Provider 返回字段。

### 手机与键盘

- 手机切换工作记录 / 成果检查，一次保留一个主要操作空间。
- 图在手机上有列表表达，不缩小字体硬塞。
- 成果页签支持方向键、Home/End 与选中焦点；导航可关闭并恢复焦点。

## 3. 本轮发现并修复

1. 样式替换在中断时暂缺文件，已恢复早期 CSS，改为新增 `studio.css`；没有删除文档、V1 或业务模块。
2. 代码块的换行与块级行共同产生过大行距，已调整空白与行布局。
3. 面板切换的事件选择器过宽，误匹配其他页面，已限定到实际按钮。
4. 桌面自动滚到底部造成顶部残留半截记录，撤回该行为，改为折叠原始目标。

问题与修复是设计层观察，不代表真实调度器或代码执行器已经经过相同验证。

## 5. 下一轮按优先级

未完成，不自动视为用户已经认可：

1. 评审两个核心画面的密度、正文尺寸、层级和配色。
2. 保留选中步骤、调用筛选、检查面板与返回位置，减少跨画面丢失上下文。
3. 把计划修改、模型切换、授权变化做成清楚的设计流程，而不是普通跳转。
4. 完善长文件名、更多模型/调用、部分失败、加载和断线时的检查体验。
5. 统一其余页面的字级与状态，清理获认可后的旧样式覆盖。

## 6. V2 第二轮：Super-agent 与 Control Panel

用户要求继续加强 Super-agent、Control Panel，并明确指出排版、操作体验和风格仍需提升，完成后提交。

新增：

- Super-agent 的项目任务协调入口：目标、分工、下一步建议、证据与人工决定。
- Control Panel 的下一次运行草稿：四个角色模型、只读并行、调用与时间上限、验证失败处理策略。
- 配置差异预览、返回编辑、撤销和非法值提示，真实应用保持禁用。
- 数值错误就近展示并与输入关联，不要求滚到底部查找原因。
- 调用筛选、成果页签、手机面板、展开的计划与滚动位置在当前文档内导航后保留。
- 中性正文与更明确的状态层级，减少偏蓝的小字，手机表单逐角色排列。

截图检查发现吸底草稿操作栏会遮挡长表单，已改为正常排版，追加输入项实际遮挡检测。

本轮 21 画面、6 视口和 14 条交互，结果见同一份 V2 verification.json。历史 V1、V2 早期样式和文档均保留。

详细边界见 [SUPER_AGENT_CONTROL_PANEL.md](SUPER_AGENT_CONTROL_PANEL.md)。可编辑交互只是静态设计中的本地草稿，不是模型、运行时或权限系统实现。

下一轮优先：

1. 用户评审新入口、编辑密度与操作路径。
2. 将计划修改做成同样明确的版本差异和影响检查。
3. 调用/步骤的精确定位和任务切换上下文。
4. 模型配置的能力、数据范围和接入状态设计。
5. 全局配色和字级统一，视觉确认后再精简旧样式覆盖。

## 8. 实现第一轮：真实只读工作区

日期：2026-11-04。用户授权“开始实现”，并询问 Mac、Linux、Android 与 iPhone 支持。

- 真实界面在 `web/`，复用本仓库原创 V2 样式与 Lucide 图标，不加载静态样例数据。
- 空工作区可以创建项目、模型与任务，启动前检查精确快照、发送位置和调用上限。
- 桌面工作/成果并列，手机使用面板切换，数字与表单输入不缩小硬塞。
- 调度、调用详情、事件和审查使用真实 API/SQLite 状态；调用用量缺失保持未知。
- 同一运行刷新时保留已展开记录和面板滚动位置；不承诺跨页签/刷新持久保存全部 UI 状态。
- 补充令牌登录/退出、移动输入字号与安全区；修复手机样式隐藏退出按钮的问题。
- 静态设计中的代码 Diff、测试与部署没有偷渡为可执行能力；当前始终显示未执行测试。

本轮验收使用 FakeProvider，截图为明确测试夹具。实际结果见 [browser.json](../tests/evidence/browser.json) 与 [实现状态](IMPLEMENTATION_STATUS.md)，不等于用户已认可视觉或完成 Safari/真机验收。

## 9. Runtime Lab：执行器对比独立预览

日期：2026-11-08。用户要求“好的，继续，可以预览吗”。

## 10. 用户未认可：回到持续工作与多端控制

本轮环境日期：2026-11-07。用户反馈“感觉没有达到效果”，要求分析 design 多版本是否能具有 Cindy + OpenMausBot/nanoMuse 等能力。

完整评审见 [DESIGN_CAPABILITY_REVIEW.md](DESIGN_CAPABILITY_REVIEW.md)。本轮只有源码、官方固定快照文档和已有截图对照，没有新增浏览器/模型/REA 运行测试。

关键判断：

- V1 继续保留，不恢复为视觉基线。
- V2 的工作记录/成果并列与手机面板切换可以复用，但长期 Agent、持续会话、跨端访问与应用连接都不是现有静态画面的真实能力。
- V2 的全局协调、任务协调和 Control Panel 入口有重叠；下一轮应按项目/会话组织日常工作，把配置和原始调用诊断置于次级入口。
- Runtime Lab 属于开发研究/协议诊断。此前将它作为主要预览偏离用户希望体验的产品闭环，不再把增加引擎卡片或协议动画当成体验迭代。
- 真实应用已有持久 Run，但 Agent 只在 Run 内，缺少会话消息；当前不能宣称已经支持成熟多 Bot 或 Cindy 式接续。

下一轮建议，不是已确认的新视觉：

1. 在同一真实工作台中保存长期 Agent、项目会话、消息与工作关联；不要再新增独立演示站点。
2. 追问进入明确的新任务/Run，沿用资料发送与成本确认，不改写在途快照。
3. 以“电脑开始、手机补充、回电脑继续”的往返闭环评审身份、同步、命令冲突和重连，而不是只看屏幕尺寸截图。
4. 之后逐项增加一个 IM + 一种只读资料源；Rust Node/执行迁移和 GUI 不偷渡为当前能力。
5. 正文、主操作、当前成果、空状态和失败恢复优先；不能用深色、页面数量或测试数量替代用户评审。

未修改历史画面、CSS 或真实业务代码；本轮没有交付新页面，也未将以上信息架构标为已接受。

随后用户追问 OpenMausBot 是否已有能力。补充澄清：上述是 mybot 缺口，不是上游缺口；下一轮优先验证复用它既有 Bot/会话及 MCP 团队控制接口，不默认自研全部功能。Bot API 的工具限制不能外推成 OpenMausBot 本身或所有接入接口缺乏能力；MCP 仍不提供审批授权，也未在本地跑过任务。
