# 研发 AI 工作台：首版范围提案

更新日期：2026-11-02。

状态：由源码对照推导的设计提案，尚未通过产品和视觉评审，没有业务实现批准。

## 1. 核心体验

> 在一个研发项目里发起工作，看到 AI 如何分工与调用模型，检查实际变更与测试证据，并决定下一步。

首版不是多 Agent 大屏，也不是自动部署工厂。它是“可做事、可追踪、可接管”的研发任务空间。

首批两条场景：

- 研发调研：对仓库或技术问题给出有来源和约束的方案。
- 修改与验证：在限定仓库中修改功能，产出 Diff、真实测试结果和审查意见，由人决定是否应用。

## 2. 首版最小能力

| 编号 | 必须有 | 最小边界 | 明确不承诺 |
| --- | --- | --- | --- |
| P01 | 项目上下文 | 目标、一个仓库/资料集、允许范围与基线版本 | 自动理解整个企业 |
| P02 | 任务计划 | 目标、验收、步骤、依赖、计划修订 | 完整可拖拽低代码编辑器 |
| P03 | Agent 分工 | 协调者与最多两个并行只读 Subagent；一个代码写入者 | 无限递归与多写入者自动合并 |
| P04 | 模型绑定 | 角色/步骤指定模型配置，记录真实请求与结果；验证两个配置 | 学习型最优路由或质量保证 |
| P05 | 安全执行 | 受控工作区、文件与测试工具、授权与权限检查 | Git worktree 等于系统安全沙箱 |
| P06 | 任务控制 | 补充输入、暂停请求、取消请求、受限重试与人工接管 | 外部副作用即时撤回 |
| P07 | 追踪可视化 | 依赖图、委派树、调用表和简化时间线可相互定位 | 发光大屏或完整 BI |
| P08 | 成果与验证 | 方案、Diff、测试命令/退出码、审查与验收 | 模型说完成就是质量合格 |
| P09 | 单次运行分析 | 排队/执行/等待耗时、用量、错误与尝试记录 | 自动根因分析和模型排行榜 |
| P10 | 审计 | 谁修改计划、选择模型、批准、执行、接管 | 未验证的防篡改承诺 |

P04 的“两种配置”可来自同一 Provider 的不同模型；首个冒烟验证可先使用一种。只有验证过至少两种模型绑定及归因，才能宣称多模型分工闭环成立。

## 3. 执行器适配的最小检查

适配器需要声明，而不是让 UI 猜测：

- 是否支持子 Agent、隔离工作区和指定模型。
- 暂停是请求、步骤边界暂停还是可中断当前调用。
- 是否可观察到实际工具结束；取消传播到哪里。
- 是否有持久事件、补取位置、稳定调用 ID 和尝试编号。
- 用量是增量、累积或包含子级汇总。
- 哪些信息只能估算，哪些字段不可得。

不满足时显示降级或禁用相应操作；不补造数据。

关键硬门槛：

1. 未授权不能写入或切换数据发送范围。
2. 子任务不能因委派而绕过授权。
3. 同一成果能追溯输入基线、计划、运行、模型/工具和验证证据。
4. 缺少隔离则保持只读或单一受限写入，不能假装可安全并行。
5. 当前调用结果不明时，先核查再恢复。

## 4. 界面中的三条事实轴

不能用一个绿点代表所有事情：

| 事实轴 | 示例 |
| --- | --- |
| 执行状态 | 排队、运行、待授权、失败、结束、核查中 |
| 验证状态 | 未执行、部分通过、失败、全部通过、证据失效 |
| 人工决定 | 待审查、要求修改、接受、拒绝 |

例如“执行结束 / 测试失败 / 等待你处理”是合法组合。“测试通过 / 尚未验收”也是合法组合。

## 5. 用量与审计

记录来源运行、步骤、Agent、模型调用与工具调用。模型请求配置与 Provider 实际返回身份分别保存，返回身份不可得则标明。返回身份是 Provider 自报，不将网关别名或自报字段宣传为已独立核验的物理后端。

计量口径：

- 每个可计量调用归集一次；父子累计不能重复加总。
- 估算成本有价格快照和时间，未知不填零。
- 并行总耗时使用墙钟时间；模型调用时间之和另列，不混用。
- 原始内容采集独立授权，默认只保留脱敏元数据与成果引用。
- 观察日志不等于安全审计；授权记录不依赖可采样遥测。

价格未知时可以限制调用数、Token 和时间，不能保证精确的金额硬上限。并行和在途调用可能继续产生消耗；预算耗尽先停止新的调度，显示尚未结算的调用。

## 6. 团队产品、单人试点

单人试点只面向受控用户，不对外开放。项目所有者、执行发起人、审批人仍作为不同责任字段建模，不能全部硬编码为“系统”。

开启多人共享前，必须先有身份认证、项目访问控制、凭证隔离和审批责任检查。SSO、组织层级和复杂计费后置。

## 7. 后续能力

代码提交/PR、CI 构建、Artifact Keeper、测试环境发布、只读运维、版本化 Skill、跨运行比较、GPU/模型实验、定时执行。

用户可以在首版产出发布建议，但不允许借此绕过未接入的正式发布工具或审批。

## 8. 首版设计验收样例

样例：为现有服务添加有上限的重试，避免重复扣款。

1. 显示基线版本、允许路径、验收要求和预算上限。
2. 研究实现与设计测试可以并行，开发写入独占工作区。
3. 选择任意步骤可进入 Agent 和实际调用。
4. 测试失败时保留 Diff 和已通过的证据，不整页显示成功。
5. 用户要求修改，形成新计划/尝试，历史仍可查。
6. 应用变更前审查具体 Diff、基线和授权对象。
7. 中断后的工具结果未知时，显示核查与接管，不提供无条件重跑。
8. 刷新、断线、重试、迟到事件与父子用量不会制造重复完成或重复计量。

以上先作为设计情节和后续 POC 用例，不表示当前能够实际执行。
