# mybot 当前产品目标与交付任务

更新：2026-11-23（Asia/Singapore）。优先级源于用户反馈：“看着没什么变化，目标呢，任务呢”。
这是产品优先级调整，不新增119项工程台账，也不把规划写成已实现。

## 总目标

让用户围绕一个研发目标，创建任务、组织多个Agent工作、看清执行过程和成果，
并能在电脑、手机和平板继续同一项工作。

```text
项目目标 -> 任务与验收 -> Agent/模型/资源安排
        -> 执行过程与人工决定 -> 成果审查 -> 下一轮工作
```

Cindy的任务接力、OpenMausBot的会话管理、nanoMuse的自托管控制能力是参考方向，
不是当前mybot已完整接入的能力。保持Astryx与一套业务界面、多样式和中英文。

## 当前能做什么

| 产品能力 | 当前事实 | 尚缺什么 |
| --- | --- | --- |
| 项目与任务 | 同一Task工作区内查看目标、验收、资料、Agent与成果 | 目标分解和任务依赖尚未实现 |

| 多Agent执行 | 固定Planning/Research/Synthesis只读流程，可配置阶段模型/指令/资源、保存与发布 | 长期Agent、更多角色、正式Harness/Model Port及任意流程 |
| 可视化 | Task/Run/Agent/Call/Artifact，固定阶段配置、版本历史与运行快照、预算和已知用量 | 任意DAG编辑、插件执行及更多Workflow对象 |
| 模型 | Codex CLI和OpenAI-compatible适配、角色模型和资源配置 | 更多Harness兼容、统一聚合用量与账单对账 |
| 多端 | 单Task设备配对/到期/撤销；独立配对端看目标/最近Run/报告、保存要求、增量GET接续 | 委托执行控制、远程HTTPS/网络、工作位置恢复、执行迁移和手机真机认证 |
| 外部工具 | 已有后端连接配置及部分只读会话适配 | 飞书/钉钉/微信/语雀/邮箱连接器及各自权限和回执 |

近期IZ切片解决了查询、分页、读取和状态一致性。2026-11-21本批新增任务工作区，
并在空闲检查/一致备份/原记录比对后更新本机4180；5173已实际使用新能力。
创建Task后进入目标/验收，显式Arrange后可在同一Task跟进Agent和审查成果。
随后ADR-0022新增“任务会话”：消息先保存，选择某条后确认资料、模型和预算，
再关联下一轮Run；未知发送/执行结果按原请求核对。本机4180已加载该能力，
5173桌面和中文手机宽度GET-only核验通过。仍是既有固定只读流程，
不是自动会话记忆或多端控制完成。11月23日ADR-0023固定Workflow初版已本机启用，
支持草稿/发布/历史版本，普通Run与任务消息均能选择旧版本，保持原快照。

## 本批具体任务结果

任务包1的初版交付如下；不是119条原工作项全部完成。

- **T0 本机版本对齐**：核实当前入口与已验收版本的差异、活动Run及可恢复备份，按已有
  启用流程完成本机版本对齐；把“代码已提交”和“用户当前入口已能使用”分开报告。
- **T1 任务入口**：提供稳定的任务工作区；从项目任务、搜索结果和待处理可进入同一个Task，
  不再必须先选列表行才能找到目标和成果。
- **T2 目标与验收**：同屏区分项目目标、任务目标、验收要求和显式资料；读取完整对象，
  不用最小引用补空字段。创建成功后进入该任务。
- **T3 安排执行**：从任务进入现有角色/模型/Harness/预算确认；保存配置、确认资料与真正
  开始执行分别有状态，不能用配置已保存冒充Agent已开始工作。
- **T4 跟进Agent**：同一任务下看到当前/历史Run、实际阶段、Agent、调用、等待/失败原因，
  再进入已有Run工作区；不复制一份执行事实。
- **T5 审查成果**：从任务直接定位成果及人工审查；成功、失败、取消、费用未知和人工接受
  分开，能够继续处理该任务。
- **T6 可见交付**：桌面/手机、中英文各走通创建→资源确认→隔离执行→成果审查路径；
  交付前后界面证据与当前本机启用状态一起报告，不以测试数量代替这个验收。

## 验收方式

每批交付说明应回答：

1. 用户从哪个入口开始，能完成什么真实工作。
2. 相比上一版，页面或操作路径发生了什么可见变化。
3. 数据来自什么已确认接口，哪些只是草稿或规划。
4. 当前本机入口是否已启用；若未启用，明确原因和启用步骤。
5. 留下最终界面证据、运行结果和未完成项；测试数量仅作支持证据。
