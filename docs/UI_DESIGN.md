## 1. 体验目标

用户面对工作，不面对基础设施。默认界面回答“当前做什么、已有何成果、需要我决定什么”；技术细节按需展开。

原创不等于发明陌生控件。保留熟悉的图标、菜单、标签、抽屉和状态表达，但不取用本地项目的布局、样式、主题或交互方案。

## 2. 信息架构提案

主导航：

| 入口 | 默认内容 |
| --- | --- |
| 工作台 | 继续的任务、待决定事项、最近成果；无大屏指标堆叠 |
| 项目 | 目标、资料、任务、决策和成果 |
| 成果 | 方案、文档、设计、Diff 和测试结果 |
| 能力 | Agent 模板、模型、工具和环境连接 |

分析先从任务内的“调用/审计”进入；全局分析与设置作为辅助入口，避免首版被模块导航分散。复杂组织管理和计费不出现在单人试点主导航；共享项目阶段加入成员与审查责任，不将身份和访问隔离留到企业管理阶段。

进入项目后，保留任务列表和项目上下文。进入任务后，对话、计划、执行与成果共用一份上下文。

## 3. 核心任务界面

```text
项目 / 任务名称          状态 · 已用预算       暂停 / 取消
----------------------------------------------------------------
任务切换      |  工作记录 / 执行图 / 调用       | 按需打开的检查区
              |                               |
当前任务      |  用户目标                     | 方案或设计预览
相关任务      |  可修改计划                   | Diff / 测试
              |  执行摘要和成果引用           | 来源 / 权限
              |  待输入或审批                 | 选中节点详情
              |-------------------------------|
              |  补充要求 / 上下文引用 / 发送 |
```

这是功能线框，不是已定版的三栏视觉。右侧默认按任务需要打开，可关闭；小屏不强行展示三栏。

默认是“工作记录”。“执行图”展示计划依赖或 Agent 委派；“调用”展示时间线和明细。切换视图保留选中步骤、筛选和滚动位置。

不得在工作台写“支持多 Agent”等功能宣传。界面文字围绕实际任务，例如“等待你确认修改范围”“3 个测试未执行”。

## 4. 六条用户旅程

### J1：首次进入

- 入口：工作台空状态。
- 操作：连接一个模型，或明确进入设计演示；无需团队和 GPU 配置。
- 反馈：显示连接测试结果、授权范围和未知的能力项。
- 下一步：开始临时任务，或创建项目。
- 异常：连接失败保留输入，说明错误类别，不泄露完整响应或密钥。
- 约束：演示数据与真实运行明确区分，未连接不能显示在线。

### J2：创建项目

- 输入：名称、目标，按需附加资料、目录或仓库。
- 操作：预览上下文范围，选择默认权限和预算。
- 反馈：显示哪些资料会发送给模型，哪些路径不可访问。
- 下一步：进入项目，启动任务。
- 异常：目录无权限、仓库无基线、资料不可读分别提示。
- 约束：调研项目不强制填写仓库、部署环境或成员。

### J3：发起任务

- 输入：目标、约束、验收条件和上下文引用。
- 操作：AI 询问必要问题，提出计划、角色分工和预算限制。
- 反馈：用户可修改步骤，查看委派模型及选择理由。
- 下一步：只读任务按策略开始；有写入动作时明确确认。
- 异常：模型能力不足、预算不明、工具未连接不能静默绕过。
- 约束：高级模型和调度配置折叠；不要求用户先搭建 DAG。

### J4：查看成果

- 入口：工作记录或全局成果。
- 操作：预览、编辑、查看来源和版本、导出。
- 反馈：区分 AI 生成、用户修改和工具验证状态。
- 下一步：补充要求、产生新版本，或启动相关任务。
- 异常：未完成、来源失效、生成失败和验证失败分别展示。
- 约束：成果不埋在长对话中，能直接定位到生成步骤及证据。

### J5：审批

- 入口：任务中的待决定事项、工作台待办。
- 内容：具体动作、目标、变更、凭证范围、预算、回退条件。
- 操作：批准本次、要求修改、拒绝；原始执行参数默认只读可展开。
- 反馈：批准后显示授权对象及版本，不立即伪装为执行成功。
- 异常：内容变化或过期时禁止旧批准，展示新旧差异。
- 约束：高风险动作不默认“本项目永久允许”。

### J6：失败接管

- 入口：失败步骤、预算不足或结果未知。
- 内容：失败摘要、关联调用、已完成成果、副作用核查状态。
- 操作：补充上下文、修改计划、切换合规模型、从安全检查点重试或人工处理。
- 反馈：保留原始尝试，新增记录；不覆盖失败历史。
- 异常：外部操作是否成功未知时，只允许先核查或明确接管。
- 约束：写入不能直接套用模型调用的自动重试规则。

## 5. 状态设计

| 情况 | 页面表现 |
| --- | --- |
| 空状态 | 一个与当前任务相关的主操作，不展示虚假统计 |
| 加载 | 保留布局尺寸，显示加载中的对象 |
| 排队 | 展示等待原因，不假装 Agent 正在工作 |
| 运行 | 展示当前动作、最近确认事件和已生成成果 |
| 等待用户 | 明确问题或审批，不保持无限转圈 |
| 断线 | 保留最后状态与更新时间，提示重新同步 |
| 部分失败 | 成功成果仍可用，失败分支单独标记 |
| 结果未知 | 明确需要核查，不自动显示失败或成功 |
| 取消中 | 区分已停步骤与仍需收敛的外部动作 |
| 完成 | 区分“执行结束”与“验收通过” |

## 6. 原创视觉方向

提案：浅色、中性、高可读的工作界面，任务内容是视觉主体。没有营销 Hero、装饰插画、发光拓扑或卡片墙。

建议 Token，仅为待评审提案：

| 用途 | 值 |
| --- | --- |
| 页面 / 内容 | `#F6F7F8` / `#FFFFFF` |
| 正文 / 次要文字 | `#20242B` / `#646D78` |
| 分隔线 | `#E2E5E9` |
| 主操作 | 深绿色 `#13795B` |
| 信息 / 警告 / 错误 | 蓝 / 琥珀 / 红，搭配文字和图标 |
| 字号 | 正文 14px，次要 12px，页面标题 22px |
| 字距 | 0 |
| 间距 | 4 / 8 / 12 / 16 / 24 / 32px |
| 圆角 | 4 / 6 / 8px |

使用 Lucide 图标。按钮控制命令，标签切换视图，菜单选择模型，开关控制二元设置，数值输入设置预算。状态不只用颜色。

实际设计、Diff 和浏览器截图用于预览真实成果，不使用无关视觉素材代替可检查内容。

## 7. 响应式与可访问性

- 宽屏：任务列表、主工作区、可选检查区；各区使用有最小宽度限制的稳定网格。
- 中屏：右侧检查区切换为抽屉，不压缩正文到不可读。
- 手机：单列任务与成果，通过菜单进入项目；图使用替代列表，不靠缩小字体硬塞。
- 文档、日志、Diff 的横向滚动限制在各自区域，不能撑宽整个页面。
- 重要操作可用键盘；焦点可见；抽屉关闭后恢复焦点。
- 图提供等价任务列表与调用表；不能仅靠悬停获取必要信息。
- 视觉稿阶段检查文字对比度、长名称、空数据、错误提示和移动端溢出。

## 8. 进入视觉稿前

先评审 J1-J6、导航及状态表，再绘制低保真页面。低保真通过后设计桌面与移动端视觉稿；现有草图不作为基础。
