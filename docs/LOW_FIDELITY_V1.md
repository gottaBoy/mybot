## 1. 总体结构

先解决一条完整体验：

```text
工作台 -> 项目 -> 任务 -> 成果与审查
                    |
                    +-> 调度 / 调用 / 审计
```

“分析”可从任务进入，保留运行与选中步骤；全局分析入口暂为次要。首版优先让用户完成工作，不要求在多个模块来回拼凑信息。

宽屏使用稳定布局：主导航约 184px；项目任务列表约 224px，进入执行后可收起；主内容最小约 600px；按需检查区约 400px。

不是四栏永远同时显示。打开检查区时，优先收起任务列表；不足宽度时检查区为抽屉。具体像素在视觉稿验证后定版。

## 2. W01：工作台

```text
工作台                     搜索项目与任务          [发起工作]
----------------------------------------------------------------
需要我处理
重试策略调整      测试失败，等待修改计划              [查看]
接口兼容性研究    等待确认研究范围                    [查看]
----------------------------------------------------------------
进行中的工作
支付服务         分析重试调用点       研究中          [继续]
发布工具         检查构建结果         工具等待中      [继续]
----------------------------------------------------------------
最近项目
支付服务         1 项运行 · 1 项待处理
发布工具         1 项运行
```

原则：

- 没有营销 Hero、全局“Agent 在线数”或虚构成功率。
- 待决定事项排在第一位。
- 空工作台只提供创建项目/发起工作，不以假数据填满。
- 数量、状态和时间均来自已确认事件；演示时必须标注为示例。

## 3. W02：研发项目

```text
项目 / 支付服务                        基线 a1b2c3   [发起工作]
目标：改进重试可靠性，避免重复扣款
[任务] [成果] [上下文] [项目设置]
----------------------------------------------------------------
重试策略调整        运行中       当前：研究实现与测试条件
接口兼容性研究      草稿         需要补充对外兼容范围
----------------------------------------------------------------
上下文摘要
仓库 payment-service     允许：src/retry、tests/retry
约束：不改生产配置       资料：接口说明 v2
```

路径权限仅为示例，不指向本机目录。

项目名称、当前基线、目标、上下文范围始终能快速找到。不同任务不共享未经授权的完整对话。共享阶段再显示成员、责任人和审查分配。

## 4. W03：任务工作区

```text
支付服务 / 重试策略调整       Run 02 · 研究中   [暂停] [更多]
执行：运行中     验证：尚未执行     验收：待审查
[工作] [调度] [调用] [审计]                 用量：可查看
----------------------------------------------------------------
目标与验收
限制重试次数；不得重复扣款；保留现有接口
----------------------------------------------------------------
计划 v2                                           [查看/修改]
1. 研究现有调用点       研究 Agent · 模型 A          运行中
2. 设计验证条件         测试 Agent · 模型 B          运行中
3. 修改与自测           开发 Agent · 模型 A          等待依赖
4. 审查证据             评审 Agent · 模型 B          等待依赖
----------------------------------------------------------------
工作记录
测试 Agent 已保存：边界测试建议                     [打开]
研究 Agent 正在读取允许范围内的调用点               [定位调用]
----------------------------------------------------------------
补充要求 / 引用资料                                 [发送]
```

这是展示分工的示例计划，不要求四个角色成为每次运行的固定流水线。模型 A/B 是未绑定的示例配置，不暗示价格或能力。

任务主操作依状态变化：草稿是检查计划/开始；运行中是暂停；待授权是查看动作；失败是检查问题；结束是审查成果。

## 5. W04：同一任务的调度视图

```text
[任务依赖] [Agent 委派]              [列表] [适应视图]
----------------------------------------------------------------
研究调用点 --------+
                   +--> 修改与自测 --> 审查证据
设计验证条件 ------+
----------------------------------------------------------------
选中：设计验证条件
职责：测试设计       模型 B       只读
输入：计划 v2、基线 a1b2c3、验收要求
输出：边界测试建议
状态：执行结束       验证：未独立验证
[查看成果] [关联调用] [授权范围]
```

两种图不混画：

- 任务依赖：工作先后与并行。
- Agent 委派：谁委派给谁、承担什么职责。

图仅表达真实状态，排队展示原因；不靠动画暗示有进展。默认只读查看，不拖拽改变已运行任务。键盘与手机提供等价列表。

## 6. W05：调用与运行分析

```text
Run 02 / 调用         筛选：步骤 · Agent · 模型 · 状态
排队时间 | 模型请求 | 工具执行 | 等待用户       数据截至 10:24
----------------------------------------------------------------
调用       Agent       模型/工具       状态      耗时   用量
mc-021     研究        模型 A          完成      实测   实测
tc-022     研究        read_file       完成      实测   不适用
mc-023     测试        模型 B          失败      实测   未返回
mc-024     测试        模型 B          完成      实测   实测
----------------------------------------------------------------
选中 mc-023
尝试 1 / 原调用归属 / 错误类别 / 下次尝试 mc-024
请求模型 / 返回模型（若不可得则未知）/ 脱敏摘要
[所属步骤] [关联成果] [原始元数据权限提示]
```

不填写假成本或假 Token。父 Agent 汇总和本次调用分开，不能在总计时重复计算。默认查看错误与等待，不把整段 Prompt 铺满页面。

## 7. W06：成果与审查

```text
重试策略调整 / 成果
执行结束         测试：2 通过 / 1 失败       验收：待决定
----------------------------------------------------------------
[方案] [代码变更] [验证证据] [审查意见]
代码变更：两个文件          基线 a1b2c3 -> 候选 d4e5f6
----------------------------------------------------------------
变更预览
限制重试次数；补充边界测试
----------------------------------------------------------------
验证证据
命令 / 环境 / 退出码 / 输出引用 / 执行时间
失败：重复扣款保护验证未通过
----------------------------------------------------------------
[要求修改] [保存结果]
应用变更：当前不可用，验证门槛未满足               [查看原因]
```

应用变更不是“成果接受”按钮的隐含副作用。主分支和环境变更需独立动作与授权；结果变化使旧审查/审批标记失效。

## 8. W07：审批与结果未知

审批：

```text
待授权：将候选变更应用到目标工作区
目标 / 基线 / 成果版本 / 实际 Diff / 访问范围
前置检查 / 风险 / 可用回退条件 / 授权有效期
[批准本次] [要求修改] [拒绝]
```

不默认给永久授权。共享阶段检查当前用户是否有权批准。

结果未知：

```text
任务已请求取消，但工具返回尚未确认
已知：模型调用停止；两个只读任务结束
未知：一次写入命令是否全部完成
已有成果仍可查看
[检查工作区状态] [人工接管]
重试暂不可用：需先核查动作结果
```

## 9. 关键交互契约

| 动作 | 必须反馈 | 禁止行为 |
| --- | --- | --- |
| 改计划 | 新版本与受影响步骤 | 悄悄改变已完成步骤 |
| 换模型 | 数据范围检查、理由与新调用记录 | 失败后跨 Provider 自动泄露上下文 |
| 暂停 | 请求已接收、实际停到哪一步 | 点击即宣称所有工具已停 |
| 重试 | 新尝试与原失败可互查 | 覆盖失败或重复未知写入 |
| 审批 | 授权对象与版本，之后另报执行结果 | 批准即显示成功 |
| 断线 | 最后确认状态及同步恢复 | 把断线当取消 |

## 10. 接下来评审什么

1. W01-W03 是否能让研发人员直接开始并推进工作。
2. W04-W05 是否足以追踪分工、模型调用和失败原因，而不喧宾夺主。
3. W06-W07 是否清楚区分成果、验证、审批和真实副作用。
4. 审查结果后再画原创视觉稿，不在本轮创建应用工程或接后端。
