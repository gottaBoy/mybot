## 3. 原创视觉建议

**主工作区：会话推进工作，成果随时可查，执行过程按需展开。**

- 项目/最近会话作为稳定入口，Agent 的角色、模型和执行位置明确区分。
- 当前工作突出目标、负责 Agent、最新进展、等待原因与下一步；避免首页堆运行时名称和系统监控指标。
- 过程显示真实步骤、工具回执与来源，可展开委派关系/时间线；不显示或伪造隐藏思维链。
- 成果检查跟随用户选择，研究报告、资料引用先做；代码 Diff、测试、浏览器/GUI 后续有真实执行再出现。
- 调用/审计为次级检查，不要求用户读原始 JSON 才能判断完成。
- 手机优先当前会话，成果/过程用面板切换；不把桌面多列压缩到小屏。
- 配色先评正文可读性、密度和状态，明暗主题不以“深色等于高级”决定。

不做角色 3D 场景、虚构在线点、无来源完成百分比、持续跳动的“思考”动画或假 tokens。需要运行图时优先成熟布局组件，不能用图节点数量替代协作能力。

## 4. 状态必须有可核查含义

| 用户看到 | 数据依据 | 不能暗示 |
| --- | --- | --- |
| 运行中/等待输入/失败 | 持久 Run 与上游明确状态、最后确认时间 | 心跳在线等于任务正常 |
| 某 Agent 负责某步骤 | 本次委派与原始 ID/父子关系 | 模型名等于长期角色 |
| 工具已完成 | 原生回执、退出码/明确业务结果 | HTTP 202 或自然语言等于完成 |
| 接受成果 | 人工决定绑定成果版本 | 代码已应用、测试通过 |
| 用量未知/结果未知 | 上游缺失、断线、未决动作 | 缺失填 0、超时等于已撤销 |

“运行过程可视化”是外部事实与允许展示的模型正文，不是采集模型内部思维链。上游例图中的“思考”文案不能成为采集授权。

### OpenAI SDK：执行库候选，不额外套一个主循环

官方文档介绍 Agent loop、handoff、guardrails、sessions 和 tracing；Graphviz 工具输出配置关系图。需要区分：

1. 设计拓扑：可能调用谁/哪些工具。
2. 运行关系：这一次真正委派了谁、哪些步骤发生了。
3. 调用追踪：具体模型/工具的状态、耗时、回执与计量。

SDK 的静态图不替代后两项。内置 tracing 默认开启，生产采用前审核数据发送与禁用配置，不能把全部提示、工具参数或资料直接导出。SDK guardrails 也不能作为 mybot 独立权限/OS 隔离的替代。

本地两条候选路线是“受控 OpenMausBot 后端”或“以后基于 SDK 的自有运行后端”，一个 Run 只选一个执行权威。当前固定只读研究流程保留，是否改用 SDK 需过兼容、全部调用预算、取消/重试、session/trace 隔离测试；不因为是 Python 就宣称零成本替换。

## 11. T3 Code：本地 Harness 控制面参考

用户新增 `https://t3.codes/` 与 `gottaBoy/t3code`。T3 Code 的定位是控制本机已经登录的多个 coding-agent CLI，不销售或代理模型额度。

这补足了 mybot 的 HarnessAdapter 方向，但不能变成“自动读取所有本地 API key”：显式环境变量配置的模型可以作为默认候选；Codex/Claude 等 CLI 只检测可执行文件并在用户明确选择后调用，复用 CLI 自己的登录态；不读取 OAuth/keyring/配置文件，不把凭证复制到 SQLite、浏览器或 prompt。T3 的手机/Web 控制能力放在 DeviceSession/Command 后置阶段；mybot 继续拥有项目 ACL、Run 预算、Artifact、审计和结果未知状态。

详见 [REA_T3CODE.md](REA_T3CODE.md)。本轮未安装 T3、未运行 CLI、未读取本机凭证。

当前 UI 约束已落地：模型设置页明确区分“本地 Harness”和“OpenAI-compatible 模型连接”。Codex CLI 显示为“已发现，认证未验证”，不会被误标为已配置模型；Adapter 需要用户显式启用，也不会读取本机登录凭证。

更新：最小 Codex Adapter 已实现。用户在模型设置页显式启用后，创建 `codex_cli` 配置；只有明确启动 Run 时才调用本机 `codex exec`，使用临时、只读沙箱参数。启用和发现不调用模型，CLI 登录态不被导出。
