# ADR-0002：研发团队定位，单人先试点

- 日期：2026-11-01
- 状态：产品定位确认，详细设计与技术待评审
- 修订对象：ADR-0001 中的“个人产品、团队以后再说”

## 最新要求

用户明确工作台主要用于研发团队，并要求分析 OpenHands、OpenBot、OpenMuse，定义现代 AI 工作台，记录重要信息和下一步。

## 决策

1. 目标产品是研发团队 AI 工作台，不是通用个人助理。
2. “先个人”保留为试点规模：先验证一位研发人员的完整工作体验。
3. 不将所有任务强制映射到需求到部署的固定流水线。
4. 仍然坚持原创 UI、先设计、按需多 Agent、模型分工、追踪、可视化、审计和分析。
5. 团队共享之前要有身份、项目访问控制、凭证隔离和审批责任。
6. 复杂组织、SSO、多租户计费等可以后置，基础安全不能后置。
7. 公开开源源码用于产品与架构分析，不代表复制其界面或确定技术底座。

## 保持不变

旧原型未采用；没有业务实现批准；外部项目未接入；不读取本地秘密、不启动付费模型或生产动作。

## 后续

完善公开源码链路分析 -> 收敛研发能力地图 -> 低保真流程 -> 原创视觉 -> 执行与数据契约 -> 经确认后开展技术 POC。
