# 图形化低保真 V1：评审说明

更新日期：2026-11-02。

状态：原创静态设计稿已绘制并完成初步浏览器检查；尚未通过用户评审、最终视觉定版或可用性测试。

## 1. 查看入口

打开 [设计稿 index.html](../design/review-v1/index.html)。它通过本地文件即可运行，不需要开发服务。

顶部选择器用于切换设计画面；任务中的关联链接用于检查任务、调度、调用和成果的连贯性。模型、审批和执行按钮均禁用，不会触发真实动作。

该目录完全独立于未采用的 `prototype/`，不取用本地其他项目的界面。

## 2. 本轮交付

| 画面 | 评审问题 |
| --- | --- |
| W01 工作台 | 能否一眼找到需要我处理的工作 |
| W02 项目 | 能否看懂目标、任务、代码基线和允许范围 |
| W03 任务工作区 | 计划、执行、记录和成果能否在一个上下文里查看 |
| W04 任务依赖 / Agent 委派 | 两种关系是否清楚，手机列表是否仍可理解 |
| W05 调用 / 详情 | 能否定位失败尝试、模型、Token、耗时与原步骤 |
| W06 代码 / 验证证据 | 是否区分变更、实际测试和人工验收 |
| W07 审批 / 核查 | 是否能理解授权范围与不确定的副作用 |
| W08 审计 | 是否能区分人、Agent、调度器与工具的操作结果 |
| S01-S06 | 首次进入、草稿、空状态、排队、断线、预算暂停 |

共 18 个画面/状态。

## 3. 固定的设计情节

- Run 02：候选变更保存于隔离工作区，2 项测试通过、1 项失败，不能应用。
- Run 03：独立的修复后审批快照，候选版本不同，3 项验证通过，仍需本次授权。
- Run 04：独立的取消后核查快照，一次文件写入结果未知，不允许盲目重试。
- Run 01：排队、断线和预算暂停的独立异常快照。

这不是在设计稿里运行了四次 Agent。所有数字、代码、日志和模型配置均为样例；全程显示静态标记。

## 4. 本轮关键取舍

1. 主导航只保留工作台、项目、成果、能力；详细分析从任务进入。
2. 三条状态轴固定可见：执行状态、验证结果、人工决定。
3. 桌面任务上下文置于旁侧；不足宽度时让主任务保留空间。
4. 手机不缩小整张图，而使用依赖/委派清单。
5. 调用表允许在自己的容器内横向滚动，页面本身不横向溢出。
6. 调用数据缺失明确写“未返回”或“未知”；片段统计不冒充整次运行。
7. 审批和核查快照不沿用 Run 02 的调用数量与关联成果。
8. 业务操作明确禁用，只有画面切换、详情查看和设计导航可用。

## 6. 验证与边界

验证脚本：[verify.mjs](../design/review-v1/verify.mjs)。实际结果：[verification.json](../design/review-v1/evidence/verification.json)。

本轮检查矩阵：

- 18 个画面，6 个视口：1920、1440、1024、768、390、320px。
- 检查全页横向溢出、图标加载、主要内容、控件截断和静态标记。
- 5 条关联导航/状态检查，包括手机导航焦点恢复、图的列表替代、失败门槛和业务操作禁用。
- 浏览器阻止外部 HTTP 请求，并要求实际请求数为零。
- 保存 16 张选定截图，人工查看了桌面任务、桌面依赖图、手机任务与手机审批。

通过结果以 JSON 中 `complete`、`failed`、`errors` 等字段为准。本轮自动检查不能代替全面可访问性、真实用户可用性、模型能力、执行安全或故障恢复验收。

## 7. 工具

本轮使用 Playwright、独立本机 Chrome 和本地图标完成检查；没有启动后端、连接浏览器登录态或使用真实工具账户。

图标来自固定版本 Lucide Static 0.468.0，原始许可随设计稿保存。验证依赖安装在临时目录，不决定正式产品框架或依赖。

本轮不需要 ego(lite)，决定见 [ADR-0003](decisions/ADR-0003-design-review-tooling.md)。

## 8. 下一步

先评审界面结构和状态表达，再处理：

- 桌面/手机字体和密度是否适合连续研发工作。
- 是否需要让调用/成果检查区支持侧栏与独立页两种方式。
- 计划修改、授权失效、模型切换与部分失败的细化设计。
- 最终原创视觉和组件状态；未获确认前不接业务后端。
