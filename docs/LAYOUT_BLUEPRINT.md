日期：2026-11-14。状态：**用户已授权继续实施，BP-01第一切片已本地实现并回归；
后续能力仍待办，视觉未获最终接受**。

从查询行移入独立结果工具带，查询仍只有一行。以下旧图中的“查询/条件/模式/视图同排”
不再作为当前空间合同；以UI_ITERATIONS第24节与可见整改前后对照为准。
依据：用户连续澄清的“顶部通用搜索独立、列表搜索一行、主组件保持 Astryx”，以及
用户提供的 Filters / Issues / Columns / Sort 截图。源码问题清单见
[PRODUCT_UI_AUDIT.md](PRODUCT_UI_AUDIT.md)；本文件解决空间归属和实现顺序，不重复
声称源码研究、旧浏览器结果或新设计提案已经集成。

## 1. 顶层结论

mybot 应是一套“找工作 → 看进展 → 查成果 → 明确控制”的研发工作台，不是把
Dashboard、表格、Chat、画布和配置模板同时堆在首页。

采用 **一套全局壳层 + 按需上下文栏 + 四类主内容布局**：

1. 全局层：我在哪个工作空间，去哪里，找哪个对象。
2. 上下文层：当前范围、项目、过滤器、资料目录或设置类别。
3. 页面层：当前对象/列表、主操作、结果内查询。
4. 内容层：列表、文档、运行过程和成果，按需打开详情。
5. 操作层：排序/列配置、审批、资源编辑和诊断，不常驻占满正文。

保持 React 19、Astryx 0.7.13、项目包装层和现有后端；不引入第二套 UI，不以改版
新增模型调用、团队权限、任意 DAG 或第三方接入。

## 2. 先看截图中的层级

截图体现的是区域责任，不是要求复制每个字段：

- 最左侧：全局导航，不受当前问题列表筛选影响。
- 中间 Filters：当前问题范围，标题与右侧 Issues 页头处于同一高度。
- 右侧：页头 → 单行结果查询/视图控件 → 条件摘要（有需要才出现）→ 表格 → 分页。
- Columns / Sort：按需弹出，主表格不因高级设置长期被占据。

蓝图制定时，mybot `FocusedWorkbench` 的标题和查询栏在 `wf-content-shell` 外，
范围栏从更下面才开始；工作视图、排序和容量又在另一条工具栏。
单行输入虽然已收紧，但整体仍不是上述区域分工。下一步要调整组合边界，
不能仅继续改字体、颜色或增加菜单。

## 3. 全局壳层

桌面目标结构示意，尺寸为设计约束，实施后仍须按内容和浏览器验证：

```text
全局导航             顶部全局栏：上下文路径 / 快速查找 / 同步 / 账户
约208px              高56px，沿用现有顶部通用搜索
------------------+--------------------------------------------------
工作入口             上下文栏          主内容
任务                 约200-224px       标题 + 范围/计数 + 主操作
待处理               ----------------+-------------------------------
项目                 常用范围          结果内搜索 / 条件 / 模式 / 视图
项目资料             项目/目录          -------------------------------
总览                 本地目录检索       列表 / 工作区 / 文档
                     可折叠            按需详情，不永久占位
资源与连接                             -------------------------------
模型与资源                             计数 / 分页
会话后端
------------------
偏好设置
开发工具（次级）
```

### 全局顶部

- 保留现有快速查找入口，不再复制一个通用搜索框。
- 查询对象：页面、项目、任务和运行；当前缺少真实任务源是 WUI-10，尚待补齐。
- 面包屑只交代位置，不同时重复显示三遍页面大标题。
- 同步状态不是模型在线或设备在线；语言、主题和账户放工具区。
- 全局搜索打开对象/导航，不改写当前列表的 q、项目或状态。

### 全局导航

- 日常入口优先，配置/实验室次级，不以模板名称作为产品导航。
- “任务”是工作主入口；“待处理”保留日常处理队列。
- 模型与资源、会话后端继续分开事实和权限，不把“已保存连接”叫作“已接入应用”。
- 路由可保留兼容，不为调整菜单删除旧地址和 `web/` 回退。
- 不提前显示没有能力的 Agent 团队、设备在线、企业 SSO 或 IM 发送入口。

### 上下文导航

- 任务页：常用状态与项目范围；保存过滤器尚未实现，不展示假的“我的过滤器”。
- 项目页：当前项目范围/资料入口，不再复制第二套独立工作台。
- 资料页：项目及目录；目录查询只过滤目录，不默默替换已选择的正文。
- 设置页：按设置类别组织；总览/Run 不强制保留无用的 Filters。
- 上下文导航内的“搜索过滤器/目录”仅查本栏，不能与顶部/结果搜索混为一谈。

## 4. 列表页，自上而下

### 第一行：页头

左：任务标题、当前范围、真实条数；右：当前页真实主操作及更多菜单。
页头约48-56px。已在全局存在的新建入口无需再放一个高权重重复按钮。
未实现保存视图之前，不复制截图中的 Save / Save as。

### 第二行：一条查询工具栏

```text
[在结果中搜索] [项目] [状态] ...       [Basic | JQL] [列表/详情] [列配置]
```

- 常见桌面宽度一行；输入框约220-320px起，不无限拉伸挤走其他控件。
- 左侧是改变“哪些记录匹配”的条件；右侧是“如何查看这些记录”的控件。
- Basic 的字段选择与范围栏共用同一查询状态，不能维护两套条件。
- 文本/JQL草稿通过 Enter 或紧凑搜索命令提交，避免再放一颗抢占页面的巨大主按钮。
- 项目/状态可即时提交，但不能覆盖尚未提交的文本草稿。
- JQL替换编辑区域，不额外叠加一整行编辑器；当前仅支持的语法仍须明确限制。
- `Natural language`、负责人、优先级等未实现语义不因截图中存在就加入可用控件。
- “更多条件”仅在确有额外字段时出现；选中条件摘要可以占可选一行，
  不把“查询必须一行”错误理解为隐藏错误或截掉用户条件。

### 第三层：结果主体

- 默认任务列：编号、摘要、项目、执行状态、最近运行、历史次数。
- 摘要占剩余空间；编号/状态/时间固定约束；桌面单行截断，详情读取全文。
- 表头约32-36px，行高目标36-40px；正文13-14px、辅助信息12px，不靠缩到10px
  获得密度。字号不随 viewport 缩放。
- 当前状态按每任务最新 Run；历史记录保留，但不作为多个当前任务展示。
- 只有提供真实批量动作时才显示选择复选框，不照搬没有后续操作的勾选列。
- 排序先作用完整结果，再分页；列显隐不改变查询结果或启动任务。
- 表格可有独立滚动区域，但 document 不能横向溢出。

### 最底部：一个结果页脚

```text
当前范围 / 总数                         [每页50] [上一页] [页码] [下一页]
```

容量和页码只保留一个操作来源，不在页头、工具栏和底部各放一套。
未知总量不填零；当前客户端 Bootstrap 分页不宣传为服务端大数据分页。

### “视图”和“对象来源”不能混淆

- 列表、看板、详情预览：可以是同一组 Task 的不同呈现。
- 运行记录：一任务对多个 Run，是不同统计单位，宜作为明确的次级入口或任务历史页。
- 后续收敛视图入口时保留现有 URL 兼容，不能静默把 Run 查询变成 Task 查询。

## 5. 截图中的列与排序菜单

建议采用一个列表配置入口，不长期常驻两三个大型设置区：

1. 可见列：真实字段列表，支持勾选；摘要/对象入口必须可到达，不能隐藏成空表格。
2. 列顺序：支持明确的上下移动和键盘操作；拖动是可选增强，不是唯一方式。
3. 排序：字段、升降序、优先级、移除和恢复默认；隐藏列仍参与排序时须显示来源。
4. 多条件排序：排序数组要贯通 URL、表格、手机和分页后再提供，不只改弹窗。
5. 分组：先定义任务/Run口径和聚合方式再开放；当前分组不支持，不展示假可用项。

当前 mybot 有单字段 order，没有列配置与完整多条件排序合同。用户之后授权继续实施，
BP-01先保留单字段排序入口，以上高级能力仍为BP-05待办，不把弹窗布局当成已接通。

## 6. 四类内容布局覆盖全站

| 页面类型 | 自上而下布局 | mybot页面 |
| --- | --- | --- |
| 查询/列表 | 页头 → 单行查询与视图 → 结果 → 分页；可选范围栏/详情 | 任务、项目、待处理 |
| 执行工作区 | 项目/任务/Run身份 → 执行/测试/人工审查三轴 → 工作/调用/成果/审计 → 过程与成果并列 | Run |
| 文档阅读 | 页头/项目 → 目录与正文 → 可选本页大纲；窄屏优先正文 | 项目资料、成果正文 |
| 配置/编辑 | 页头 → 类别与设置行 → 编辑/验证 → 明确结果；长流程分步 | 模型、后端、资源、偏好 |

总览是上述真实读模型的摘要：当前任务、异常、最近任务动态；不再成为第二个运行
诊断台，也不把同任务的旧失败铺成多个当前失败。

### Run 工作区

- 首屏先回答“当前做什么、什么状态、成果在哪、需要我做什么”。
- 工作过程与成果约60/40可调；调用原文/审计/诊断次级打开，不将所有内容同时展开。
- 暂停/取消/重试按执行状态、权限和费用确认呈现，不能当普通外观按钮。
- 固定阶段图保留为运行投影，不扩大成可执行任意工作流设计器。
- 小屏默认过程或成果单一主面，使用明确切换，不强行压缩双栏。

### 配置页面与表单

- 设置行展示身份 → 保存/测试/认证/能力事实 → 当前可执行动作。
- 普通配置使用中等宽度的 Dialog/Drawer；复杂资料/资源/同意流程使用分步确认。
- 连接失败、未知结果、无权限、撤销和未配置区分；保存成功不能涂成能力已验证。
- dirty关闭、字段错误、快照冲突和未知调用重试属于交互合同，不是仅调CSS。

## 7. 响应式：按可用内容宽度减法

| 可用场景 | 导航 | 内容与详情 |
| --- | --- | --- |
| 宽桌面，约1440px以上 | 全局208px；上下文200-224px可折叠 | 表格主面，详情按需打开 |
| 开详情后表格不足约720px | 优先收起上下文栏 | 不把摘要压成极窄的一列；详情约320-400px |
| 中等桌面，约1024-1439px | 全局可缩为图标栏；上下文进入抽屉 | 保证主列表优先，工具次项合并进菜单 |
| 平板，约768-1023px | 全局/范围按需抽屉 | 一个主内容面；详情替换主面或抽屉，不堆四栏 |
| 手机，小于约768px | 同一导航数据，抽屉呈现 | 任务行替代表格；筛选/列设置移至面板，保留单行核心查询 |

这些是目标约束，不是当前断点已经改好。最终通过容器可用宽度、长中文/英文、
触摸键盘和真实截图调整。不能用统一缩小字体代替收纳，不让隐藏触发器承接焦点。
普通页面只保留一个主纵向滚动区；大表格/长日志可以独立滚动，页头和工具区不能盖住内容。

## 8. Astryx 与样式边界

| 责任 | 复用方向 |
| --- | --- |
| 壳层/上下文/页头 | 项目自有组合，继续复用现有 Astryx 控件；不为升级而替换已验证行为 |
| 一行查询 | TextInput / InputGroup / Selector / SegmentedControl |
| 字段条件 | 真实字段合同成立后采用 PowerSearch / ComplexSelector |
| 列/排序/表格 | Table及列配置/列宽/排序插件，项目封装维护状态 |
| 手机面板/复杂动作 | Dialog / Drawer / BottomSheet / DropdownMenu |
| 运行与资料 | TabList / Resizable / ScrollableArea / Markdown |

- 一套业务树、一套语义 Token；Neutral/Zira等配色只改变外观，不复制页面。
- style、明暗、密度、语言独立；舒适/紧凑必须作用到表格、设置行和记录行。
- 采用4/8/12/16/24间距层级，页头20-22px、分区14-16px、正文13-14px、辅助12px。
- 页面区域不做浮动大卡片，不靠卡片套卡片制造层级；边框/留白/标题表达区域。
- 颜色只表达重点和状态，unknown不画成成功。图标沿用Lucide，工具有可访问名称。
- 仅安装包能力核查：不代表所有候选组件已经接入或验收。

## 9. 实施顺序与停止点

| 顺序 | 范围 | 完成门槛 |
| --- | --- | --- |
| 1 | 全局壳层与任务页区域重组 | Filters与页头同层；顶部/列表搜索分离；宽屏单行；手机不溢出；保留查询 |
| 2 | 主任务/项目/待处理共用页面模式 | 不维护第二套工作台；计数单位一致；列表返回和焦点成立 |
| 3 | Run与资料布局 | 过程/成果主次清楚；调用实时更新；目录查询不偷换正文 |
| 4 | 模型/后端/表单 | 保存/验证/未知清楚；错误就近显示；dirty、409和重试有明确路径 |
| 5 | 列配置、多条件排序、规模化控件 | 状态合同/URL/键盘/分页/手机完整，再添加可见控制 |

每一步更新审计WUI状态、进度和截图，先验证一类布局，再迁移同类页面。
不承诺一次覆盖所有功能；不删旧设计/旧web，不自动迁移数据库/调用真实模型。
视觉评审与功能回归分别记录，用户未接受前不把此蓝图称为最终设计。
