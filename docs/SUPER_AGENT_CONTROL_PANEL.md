# Super-agent 与 Control Panel

日期：2026-11-02。状态：静态交互设计提案，未接模型或执行器，尚未通过用户体验验收。

## 1. 两个入口，各自有明确职责

| 入口 | 内容 | 不承担 |
| --- | --- | --- |
| Super-agent | 当前目标、验收、分工、证据与下一步建议 | 自行修改权限、编造执行状态 |
| Control Panel | 下一次运行的模型与资源草稿、项目权限检查 | 修改历史 Run、启动真实任务、永久授权 |

两个入口始终显示项目、任务、代码基线和 Run 02 已结束，避免被误解成全局管理员控制台或运行中的生产调度器。

可以从主导航、任务中的协调页签、Super-agent 署名及任务标题旁的控制图标进入；回到任务仍保留检查上下文。

## 2. Super-agent

展示：

- 目标与三项验收，验证失败单独标记。
- 基于现有报告的修复建议，关联实际示例证据。
- 开发修复、重新验证的建议顺序，明确未执行。
- 本轮 Agent 与模型分工，可进入调用或验证证据。
- 人的最近决定和不能自动越过的边界。

“准备修改要求”进入草稿，不直接运行修复。“调整下一次运行”进入 Control Panel，不修改已完成 Run 02。

没有新增 Agent 群聊、自动自评或不可信的完成百分比。

## 3. Control Panel 的交互

仅在浏览器当前页面会话内编辑：

1. 为协调、研究、开发、测试选择两个样例模型配置之一。
2. 设置只读并行上限、模型调用数和运行时间。
3. 查看并修改“验证失败后暂停后续调度”的草稿；关闭也不能绕过应用变更门槛。
4. 对空值、小数和越界值在输入项旁展示关联错误，并禁止预览。
5. 有有效改动时才启用“预览调整”，展示逐项原值与新值。
6. 可以返回编辑或撤销，刷新后恢复初始草稿。

草稿和差异没有被写入 Run 02、审计历史、模型请求或执行器。应用按钮持续禁用，页面明确标识未应用和未连接。

模型与调用上限是可讨论的设计值，不代表这些连接已可用或本项目已具备资源控制能力。

## 4. 控制与安全语义

- 模型变更不扩大目录、工具或数据发送权限。
- 代码写入仍需独立授权；多人共享时还需检查审批人身份与项目权限。
- 原运行、成果、验证和授权记录不随草稿变化。
- 价格未知时只提供调用、Token 或时间边界，不能承诺精确金额上限。
- 达到上限停止新调度，不代表在途调用已经停止计费。
- 操作日志不能作为防篡改证明，当前也不伪造“配置已应用”的审计事件。

## 5. 排版与体验改进

- 正文和主要操作提高可读性，减少偏蓝的小字。
- Super-agent 的建议、依据、执行顺序与用户决定分开，不做装饰性大屏。
- 模型和资源使用选择器、数值输入和开关，不用按钮模拟设置项。
- 控制表单在手机改为逐角色的单列编辑。
- 操作栏正常排版，避免吸底层遮挡输入项；检查脚本实际命中输入中心检查遮挡。
- 修改角色模型后返回编辑保留草稿；切换任务视图保留成果页签、手机面板、调用筛选、展开状态及滚动位置。
- 上述状态只保留在当前文档会话，不承诺刷新、重启或跨设备恢复。

## 6. 静态验证

本轮矩阵扩为 21 个画面、6 个视口（126 项渲染），14 条交互检查。

新增验证：

- 任务范围和 Super-agent 的未执行状态。
- 模型/预算修改、差异预览、返回编辑、撤销与刷新重置。
- 非法数值的提示和预览阻止。
- 调用筛选在进入详情再返回后保留。
- 手机成果面板、验证页签和展开计划在导航后保留。
- 数值输入项不被操作栏等元素遮挡。

实际结果与截图：[verification.json](../design/review-v2/evidence/verification.json)。

此验证不能代替真实调度、权限、持久化、全面无障碍或用户可用性验收。
