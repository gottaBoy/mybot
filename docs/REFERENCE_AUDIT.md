# 本地能力评估

更新日期：2026-11-01。

这是源码与文档阅读记录，不是联调或验收报告。以下项目当前均未接入 mybot；本次未启动服务、调用付费模型或读取凭证。

## 1. 统一边界

mybot 的视觉、布局和交互全部原创，不借鉴 `/home/my/workspace/ainfra` 下的项目。已有项目只评估后端接口、执行能力和工程经验。

源码存在不等于服务运行；README 描述不等于部署验证；测试文件存在不等于本次测试通过。

| 项目 | 能力候选 | 当前决定 |
| --- | --- | --- |
| agent-delivery-platform | 工作流、审批、DAG、渠道适配 | 评估，不整体照搬 |
| my-ai-swarm | 本地执行、worktree、checkpoint、合并检查 | 执行器候选 |
| artifact-keeper | 包、镜像、扫描、制品接口 | 发布阶段再评估接入 |
| mattermost | 通知、讨论、审批渠道 | 单人试点不依赖 |
| aibiz | 数据建模与大型工程经验 | 不引入 UI 或运行时 |

## 2. agent-delivery-platform

已阅读 `app/statemachine.py`、`workflow.py`、`task_dag.py`、`orchestrator.py` 和 `models.py`。

阅读到状态转换、乐观锁、审批 hash/TTL、DAG、设计/代码/QA 编排和审计模型。

需要验证：

- 固定软件交付阶段不能直接表达全部个人任务。
- 进程内锁和内存 DAG 不等于跨进程持久化恢复。
- `actor="human"` 标记不等于用户认证和真实授权。
- 审批、受保护动作和状态转换是否原子关联。
- 计划修订、取消、副作用核查和事件流是否满足新契约。

结论：领域与后端候选，不将 21 个阶段直接变成产品导航或所有任务的生命周期。

## 3. my-ai-swarm

已阅读 README、`src/orchestrator.mjs`、`contracts.mjs` 和 `web-server.mjs`。

阅读到角色输出校验、checkpoint、取消/恢复、worktree 和合并检查逻辑；具体恢复与隔离效果尚未在本项目验证。README 说明现有控制台没有内置登录，不应直接暴露给不可信网络。

结论：执行器候选，不继承其界面，不在当前阶段启动真实任务。

## 4. artifact-keeper

已阅读 README 和 `docs/dgx-arm64.md`。

README 描述制品、OCI、扫描和存储能力。DGX 说明记录了部分上传下载、OCI、扫描及 SBOM 测试，也明确列出晋级门禁、Webhook、完整权限等未验证项。

这是该项目的历史说明，不是 mybot 集成证据。当前服务状态、API 版本和完整发布流程尚未核查。

用途：

- 工作成果：方案、设计、Diff、测试报告，由工作台组织版本与索引。
- 发布制品：镜像、包，通过可选适配器上传，关联代码版本与 digest。
- 扫描完成、结果通过和允许发布分别表达，不混成一个“成功”。

结论：有发布需求时优先评估，不要求单人试点安装完整制品与扫描栈。

## 5. mattermost 与 aibiz

Mattermost：已阅读 README 与目录结构，当前目录主要包含二进制和编译后客户端。可选通知与审批入口，不决定产品信息架构；消息不能代替任务状态。

aibiz：已阅读 package、View Shell 和部分 Agent 实体。撤回此前 UI 借鉴建议，不复用主题、布局、导航、Dashboard、弹窗或 iBiz Runtime，也不据此确定前端框架。

## 6. 任何接入前

1. 明确实际需要的能力与不可用时的退化行为。
2. 确认版本、认证、权限、数据范围及具体许可证要求。
3. 使用专用最小权限凭证，不向 Agent 交付管理员密钥。
4. 验证成功、失败、超时、重复请求和中断。
5. 保存实际证据与未验证项，再决定是否作为默认能力。

未接入的服务在界面显示“未连接”，不展示为在线或已经验收。
