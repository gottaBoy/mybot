# 可视化调度与追踪

更新日期：2026-11-02。

状态：设计提案。当前没有真实调度器或遥测接入。

对应的任务工作区、执行图和调用线框见 [LOW_FIDELITY_V1.md](LOW_FIDELITY_V1.md)，已读源码与适配差异见 [SOURCE_CHAIN_ANALYSIS.md](SOURCE_CHAIN_ANALYSIS.md)。图、委派、计量等能力仍需通过实际后端验证。

## 1. 可视化要回答的问题

- 哪些任务有依赖，哪些可以并行？
- Super-agent 把什么工作交给了谁？
- 哪个模型正在调用，为什么选择它？
- 卡在排队、模型、工具、审批还是合并？
- 失败、重试和成本来自哪次调用？
- 用户干预之后，哪些计划和动作发生了变化？

不把任务、Agent、模型和工具混成同一种图节点。

## 2. 一份数据，三个主视图

### A. 任务执行图

节点是计划步骤，边表示依赖。节点显示工作名称、角色、模型摘要、状态和待决定事项。

```text
确认目标 -> 资料研究 A --+
         -> 资料研究 B --+-> 汇总结论 -> 审阅 -> 保存方案
```

支持选中步骤、聚焦失败分支、切换等价列表。完成百分比未知时不编造“预计完成 80%”。

### B. Agent 委派树

节点是 Agent 调用，边表示父子委派，不表示业务先后关系。

```text
Super-agent：统筹本次任务
  Research Subagent：资料 A，模型 X
  Research Subagent：资料 B，模型 Y
  Review Subagent：检查结论，模型 X
```

角色名旁显示实际模型，不把角色等同于固定模型。一个 Agent 可有多次模型调用，每次调用都有独立记录。

### C. 调用时间线与明细

按 Agent 或模型分泳道，展示排队、请求、工具等待、审批和重试。点击调用进入经过脱敏的参数摘要、错误、用量和证据。

首版先提供可筛选调用表及简化时间线；完整缩放瀑布图、跨运行对比和大规模拓扑后置。

## 3. 页面交互

- 默认工作记录，不以复杂 DAG 迎接新任务。
- “执行图”内切换任务依赖和 Agent 委派。
- 选中节点后在检查区显示负责者、模型、输入输出引用和关联调用。
- 从模型错误可以回到对应步骤、成果和重试尝试。
- 图仅反映已确认调度状态，模型输出的计划是建议，不直接驱动画布状态。
- 不默认允许拖拽运行中的节点改变执行；改计划需先处理受影响步骤。
- 视图可重连并恢复筛选，动画不应代替真实状态。

## 4. 模型选择与调度

建议调度顺序：

```text
目标 -> 版本化计划 -> 等待依赖 -> 检查权限与预算
     -> 筛选模型与执行环境 -> 分配 -> 执行
     -> 保存证据 -> 汇聚 / 审批 / 恢复 / 完成
```

硬条件：用户允许的 Provider、数据出境范围、必要工具/结构化/视觉能力、输入长度、预算和资源限制。

软条件：已验证任务效果、延迟、可用容量和估算成本。首版使用可解释规则或手动选择，不宣称已经具备学习型最优路由。

界面显示：

- 最终选择与简短理由。
- 未满足的约束和没有合适模型的原因。
- 路由规则、能力验证与价格快照版本。
- 发生回退时的原模型、新模型、触发原因和新调用记录。

不能因某提供商故障而自动绕过隐私约束。修改中的任务也不能未经确认切换执行器继续写入。

## 5. 追踪与审计分离

| 记录 | 用途 | 保存要求 |
| --- | --- | --- |
| 任务事件 | 还原任务、步骤和状态 | 持久化，不能依赖遥测采样 |
| 调用追踪 | 关联 Agent、模型、工具及耗时 | 有稳定关联 ID，标注缺失数据 |
| 审计记录 | 计划变更、授权、写入和人工操作 | 首版追加记录；不可宣称已防篡改 |
| 成果引用 | 定位方案、Diff、测试与版本 | 与生成运行和证据关联 |

关键关联 ID：project、task、run、plan_revision、step、agent_run、parent_agent_run、model_call、tool_call、approval、artifact_version、trace/span。

事件需要事件 ID、运行内顺序、实体版本、发生与接收时间。重复和乱序消息不能重复推进状态；断线后从已确认位置补取。重试保留原调用，不覆盖历史。

## 6. 指标口径

- 排队、执行、模型、工具、等待人工分别计时；并行耗时不能直接相加当作总耗时。
- Token 与成本在实际计量的叶子调用归集；父 Agent 展示汇总，但报表不能重复累加。
- 重试、失败调用和缓存用量单独保留，按 Provider 实际口径标记。
- 价格未知不填零；本地推理无 API 账单不等于无资源成本。
- Agent 声明完成、运行结束、工具验证和用户验收是不同维度。
- 首版不根据模型自评分生成虚假的质量排名。

执行结束、验证通过、人工接受按三条事实轴显示；详细例子见 [MVP_SCOPE.md](MVP_SCOPE.md)。执行器如果只提供父子累计值而没有叶子明细，展示累计范围和缺失项，不能把拆不出的数值伪装成逐调用精确成本。

## 7. 人工干预

支持暂停、取消、补充上下文、修改未开始的计划、批准具体动作、按条件重试及人工接管。

暂停与取消采用请求/确认两阶段显示。工具动作结果未知时进入核查；对有副作用的操作不提供无条件“全部重试”。

新指令产生计划修订。已开始、依赖被改变或审批已发出的步骤需要展示影响，不能静默替换。

## 8. 参考与验证

OpenTelemetry 的 GenAI 约定可以作为模型用量和调用追踪的字段参考，不等于已经接入，也不能代替业务任务状态与审计。

公开参考在 2026-11-01 查阅；该约定仍有演进，实施时需固定版本并维护内部字段映射，不让外部字段变化直接破坏 UI。

```text
https://opentelemetry.io/docs/specs/semconv/gen-ai/
https://opentelemetry.io/docs/specs/semconv/gen-ai/gen-ai-metrics/
https://github.com/open-telemetry/semantic-conventions-genai
```
